# A11y Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development, as modified by the **Execution** section below (ponytail implementers, a Codex adversarial review per task, a ponytail adjudicator, and parallel waves in git worktrees). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an agent on Agentverse that other agents hire to run an automated accessibility scan and keyboard walk on a URL, then return verified deterministic fixes, the criteria left untested, and a signed scan log.

**Architecture:** One Python process runs a uAgents `Bureau` with four agents. `a11y-lead` connects through the mailbox and handles the Chat and Payment Protocols; `scanner`, `walker` and `fixer` are subagents. The lead talks to them through typed Models and a job-id future registry. All browser work goes through one guarded Playwright module (SSRF checks, caps). Pure logic sits in `gate/` and is unit-tested; agent glue sits in `agents/` and is smoke-tested. It is deployed as one always-on Fly.io machine.

**Tech Stack:** Python 3.12, `uagents>=0.25.5`, `uagents-core` (chat and payment protocols), `playwright` (Chromium), axe-core 4.14.0 (vendored JS), `beautifulsoup4` + `soupsieve`, `cryptography` (ed25519), `cosmpy` (Dorado testnet), `pytest` + `pytest-asyncio`, Docker + Fly.io.

**Spec:** `docs/superpowers/specs/2026-11-03-a11y-gate-spec.md` (the council verdict). Event rules are in `stranger-builds-fetch-challenge.md`.

## Global Constraints

- The words "pass", "compliant", "certified" and "agent-ready" never appear in any agent output, the README or the agent profile. The only exception is the phrase "legal compliance certification" inside the disclaimer.
- The pitch copy is taken verbatim from the spec's "Pitch" section.
- Agentverse registration uses the **uAgents** option (mailbox). No adapter frameworks.
- Status is `automated_status: "violations_found" | "no_automated_violations_detected"`.
- Every report includes this disclaimer verbatim, with X, Y and Z filled in: "Automated scan result: X violations found across Y tested WCAG 2.2 AA success criteria. Z criteria require manual/human testing and were NOT evaluated. This is not a WCAG conformance determination or legal compliance certification. Suggested code changes are unreviewed and must be checked by a developer before use."
- axe-core is exactly 4.14.0, run with tags `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`.
- Input is a single http(s) URL. No crawling and no pasted HTML.
- Caps: 30 s wall time per page and 2 MB HTML.
- Browser setup: a new browser context per job, downloads blocked, `reduced_motion="reduce"`, viewport 1280x800.
- Every request, redirect and subresource is checked against private, loopback, link-local, metadata and RFC1918 ranges, after DNS resolution.
- The fixer is deterministic. There is no LLM anywhere in v1.
- Patch allowlist:
  - May add or modify only `alt`, `aria-*`, `role`, `lang`, `for`, `tabindex` (≥ -1), the `<title>` element, and inline `color` / `background-color`.
  - Rejects any change to `href`, `src`, `action` or visible text nodes, any element deletion, `<script>`, `on*` attributes, `javascript:` URLs, and `aria-hidden` or `display:none` on focusable or content nodes.
- Walker:
  - Up to 50 Tab presses.
  - Logical-order and obscured-focus checks are `needs_review`, never `fail`.
- Free tier: 5 scans per sender address per UTC day. In memory; it resets on restart.
- Paid tier:
  - Patch plus receipt costs 0.5 FET (`500000000000000000` atestfet) via `fet_direct` on Dorado (`fetchai_stable_testnet`).
  - Always labelled TEST. Live charging is off.
- Nothing is stored by default. Logs hold only rule ids, hashes and job ids.
- Secrets come from environment variables only: `LEAD_SEED`, `SCANNER_SEED`, `WALKER_SEED`, `FIXER_SEED`, `RECEIPT_KEY_HEX`, `BUYER_SEED`, `BUYER_WALLET_MNEMONIC`. Never commit them.

## Review Focus

1. **A URL that resolves or redirects to a private or metadata address** (e.g. 169.254.169.254) is refused before any content loads. The result is an error report, not a crash or a hang. Test in Task 2.
2. **A page that never finishes loading or exceeds 2 MB** returns `error="timeout"` or `error="too_large"` within the cap. The agent still replies. Test in Task 2.
3. **A clean page with no violations** still returns the disclaimer, the untested criteria and the keyboard-walk summary. The rendered text never contains "pass" or "compliant". Test in Task 4.
4. **A chat message with no URL, or with a `file:` or `javascript:` URL,** gets a one-line usage reply and no scan. Test in Task 5.
5. **A fix that introduces a new violation** is dropped and labelled `regressed`, and the returned patch excludes it. Test in Task 9.

## Execution

These rules override the defaults in superpowers:subagent-driven-development (SDD). Where SDD and this section disagree, this section wins.

### Roles

| Role | Who | Model | Job |
|---|---|---|---|
| Controller | main session | session model | Runs the waves, the ledger, merges and rulings. Never writes product code. |
| Implementer | `general-purpose` subagent, one per task | sonnet; opus for Tasks 5, 7 and 9 (integration and algorithm work) | First action is `Skill ponytail:ponytail` (level full). Then it follows the SDD implementer template: TDD, commit, write its report to the report file. It never spawns subagents. |
| Reviewer | Codex adversarial review, run by the controller | Codex | Challenges each finished task. Review only. |
| Adjudicator | `general-purpose` subagent, one per review | sonnet | First action is `Skill ponytail:ponytail`. Rules on every Codex finding (see "Escalation" below). |
| Final reviewer | SDD final whole-branch review | opus | Runs once, after Wave D. It also gets the ledger's parked and deferred lines. |

### Per-task loop (replaces SDD steps 3–4)

1. **Implement.** Record `BASE=$(git rev-parse HEAD)` in the task's worktree. Generate the brief with SDD's `scripts/task-brief`, then dispatch the ponytail implementer with the brief path and the report path. The task's goal is met when the implementer reports DONE and every test the brief names passes.

2. **Run the Codex adversarial review.** In the task's worktree, the controller runs:

   ```
   node "$HOME/.claude/plugins/cache/openai-codex/codex/1.0.5/scripts/codex-companion.mjs" adversarial-review --wait --base $BASE "Task N of docs/superpowers/plans/2026-11-03-a11y-gate.md. Challenge the approach against the Global Constraints and Review Focus. Hunt for: SSRF bypasses, banned-word leaks, allowlist escapes, double-spend on payments, false 'fixed' outcomes."
   ```

   Run it with `run_in_background: true` whenever another task in the wave is still running. The output is saved verbatim to `<workspace>/task-N-codex.md`. The controller does not read it into its own context beyond the findings list.

3. **Escalate.** Dispatch the ponytail adjudicator with the brief path, the Codex file path and the review package from SDD's `scripts/review-package`. For each finding, it returns exactly one of:
   - `FIX` — a real defect: a bug, a security issue, or a spec or Global Constraints violation. Comes with a one-line minimal fix.
   - `REJECT` — over-engineering or speculative ("add when X"). Comes with a one-line reason.
   - `DEFER` — real, but not load-bearing before 9 Nov.

   Security findings, meaning anything in Global Constraints' safety lines or Review Focus 1–2, may never be `REJECT`ed for being "too much code". The ponytail rule "never simplify away security" applies.

4. **Fix.** Resume the original implementer with the `FIX` list verbatim. Then run a scoped Codex re-review over the fix diff: `adversarial-review --wait --base <FIX_BASE>` with the focus text "verify these fixes: …". The new findings go back through the adjudicator. Fix-loop caps follow SDD's rules (5 rounds; rounds 4–5 use a fresh implementer on opus).

5. **Ledger.** Write `REJECT` and `DEFER` lines to the ledger as `Task N: Ruling: <finding> — <adjudicator reason> — <cost if wrong>`. These lines are listed in the final message under "Rulings I made".

### Parallel waves (overrides SDD's "never parallel implementers")

Parallel tasks run in isolated worktrees: `Agent` with `isolation: "worktree"`. Each runs on its own branch, `task/N-<slug>`, cut from the current `main`. When a task's loop is clean, the controller merges its branch into `main` with `--no-ff`. Merges happen one at a time, in task-number order. After each merge the full suite (`pytest -v`) must be green before the next merge. If a merge conflicts or turns the suite red, the controller resumes that task's implementer on a fresh rebase. The controller never resolves conflicts by hand.

| Wave | Tasks (run in parallel within a wave) | Needs | Shared files |
|---|---|---|---|
| 0 | 1 | none | none |
| A | 2 (browser), 4 (report), 8 (fixer, allowlist, contrast) | Wave 0 | disjoint |
| B | 3 (scanner), 7 (walker), 10 (receipt) | 2 (for 3, 7) and 4 (for 10) | disjoint |
| C | 5 (agents, wires the real scan, walk and fix), then 6 (deploy) | A, B | serial |
| D | 9 (gate, plus receipt wiring), then 11 (payment), then 12 | C | serial |

At most 3 implementers run at once. Merging Waves A and B before Wave C is what keeps `agents/` single-writer.

### Preflight (controller, before Wave 0)

- Run `node "$HOME/.claude/plugins/cache/openai-codex/codex/1.0.5/scripts/codex-companion.mjs" setup`. The checks must show no failing `auth` line. On 2026-11-03, auth showed `connect ENOENT … codex-app-server`; if that persists, ask the user to run `! codex login`. This is a stop condition, because it involves credentials.
- Task 1 runs `git init`. Codex review needs a git base, so Wave 0's review uses `--base $(git rev-list --max-parents=0 HEAD)`.
- SDD's pre-flight scan table goes in the ledger as normal.

### Stop conditions (in addition to SDD's four)

- The human-only steps in Task 6: `fly launch`, `fly secrets set`, connecting the mailbox in the Inspector, and creating and pushing the public GitHub repo. Also Task 12 step 2 (outreach messages sent as the user) and step 4 (trials and videos). The controller prepares everything for these steps and asks the user to run them.

### Task 5: Agents, Bureau, chat (scan and walk path)

**Files:**
- Create: `gate/quota.py`, `gate/chat.py`, `gate/pipeline.py`, `agents/__init__.py`, `agents/rpc.py`, `agents/subagents.py`, `agents/lead.py`, `tests/test_chat.py`, `tests/test_pipeline.py`

**Interfaces:**
- Consumes: Tasks 1–4, plus `walk` (Task 7) and `fix` (Task 8).
- Produces:
  - `Quota(limit: int = 5)` with `.allow(sender: str, day: date) -> bool`, which increments the count on true.
  - `parse_chat(text: str, sender: str, quota: Quota, today: date) -> Action`, where `Action` is one of:
    - `Scan(url)` for `check <url>` or a bare URL
    - `Fix(url)` for `fix <url>`
    - `Reply(text)`
    - Only the first `https?://\S+` counts. Non-http input, no URL or an exhausted quota returns `Reply`. `Fix` never consumes quota, because it is paid.
  - `USAGE: str`: "Send `check <url>` for a free automated scan, or `fix <url>` for a verified patch + signed scan log (0.5 TEST FET)."
  - `ScanFn = Callable[[ScanRequest], Awaitable[ScanResult]]`, and likewise `WalkFn` and `FixFn`.
  - `async run_gate(job_id: str, url: str, scan: ScanFn, walk: WalkFn, fix: FixFn | None) -> Report`. In this task it runs scan and walk concurrently and merges findings and tested criteria. If either returns an error, it returns `build_report(..., error=...)`. The `fix` branch arrives in Task 9.

- [ ] **Step 3: Implement `walk`**

  This algorithm isn't determined by the tests alone, so follow it exactly:

  ```
  T = JS: visible focusable elements (a[href],button,input,select,textarea,[tabindex]:not([tabindex="-1"])), excluding disabled/hidden
  modal = JS: first visible [aria-modal="true"], dialog[open]
  if modal: focus its first focusable; press Tab 10x; any activeElement outside modal -> modal-focus-escape fail
            press Escape; if modal still visible or focus not on opener -> modal-focus-return needs_review
            reload page before the main walk
  main walk: press Tab up to max_presses; after each, record unique CSS path of document.activeElement
    stop early when activeElement returns to the first recorded element (cycle complete)
    for each newly focused element: screenshot its box+4px before focus (blur first) and after focus;
      identical bytes -> focus-not-visible fail at that selector (cap 10 checks)

  for each element of T never visited -> kbd-unreachable needs_review (cap 10)
  ```

**Interfaces:**
- Consumes: `Finding`, `Fix` and `FixResult` (Task 1).
- Produces:
  - `contrast.ratio(fg: str, bg: str) -> float`, using the WCAG relative luminance formula on hex colours.
  - `contrast.fix_fg(fg: str, bg: str, target: float) -> str`. It steps the fg HLS lightness by 0.01 toward whichever of black or white gives the higher contrast against bg, and returns the first hex with ratio ≥ target.
  - `allowlist.patch_violations(before: str, after: str) -> list[str]`, which is empty when the patch is allowed.
  - `fix(html: str, findings: list[Finding], rules: set[str] | None = None) -> tuple[str, list[Fix]]` returns the patched HTML. It applies only rules in `rules` when that is given. Each fix's outcome starts as `fixed` (applied) or `needs_author`; the pipeline downgrades outcomes in Task 9. If `patch_violations` is non-empty for a rule's change, that change is reverted and marked `not_fixed` with the violation as its note.
- Rule handling:
  - `html-has-lang`: set `lang="en"`.
  - `document-title`: insert a title from the first `h1` text, otherwise the hostname.
  - `color-contrast`: set inline `color` to `fix_fg(data.fgColor, data.bgColor, data.expectedContrastRatio)`.
  - `button-name`, `link-name`, `label`, `select-name`: set `aria-label` from the first non-empty of placeholder, title, name, or the nearest preceding text. Note "verify wording".
  - `duplicate-id`: append `-2`, `-3` and so on.
  - `image-alt`: no change; `needs_author`.
  - Any other rule: `not_fixed`.

  patched, fixes = fix(FixRequest(html=html, findings=base.findings, rules=sorted(candidate)))   # FixFn; the subagent wraps Task 8's fix()

  diff = difflib.unified_diff(html, final_patched, "original", "patched")
